# Alert

Alerts communicate important information to users in a prominent, contextually appropriate way. The ELEVATE Alert component helps designers and developers create consistent feedback systems that enhance user understanding while maintaining interface harmony.

<TocLinks />

## Overview

### When to Use Alerts

- **System feedback**: Confirm successful actions, warn about potential issues, or report errors
- **Important announcements**: Notify users about system updates, maintenance, or feature changes  
- **Contextual guidance**: Provide helpful information or tips related to current user tasks
- **Status updates**: Communicate the current state of processes, applications, or user accounts
- **Validation messages**: Display form validation results, input requirements, or submission status

### When NOT to Use Alerts

- **Toast notifications**: Use Toast component for temporary, dismissible messages
- **Inline validation**: Use field-level validation for immediate input feedback
- **Loading states**: Use Loading or Progress components for process indicators
- **Permanent navigation**: Use appropriate navigation components for persistent interface elements
- **Decorative messages**: Use appropriate content components for non-critical information

## Design Principles

### Clarity Principle
**Alert content should be immediately clear and actionable.** Use concise, specific language that helps users understand the situation and what they should do next.

### Context Principle  
**Alerts should appear in contextually appropriate locations.** Position alerts near relevant content or actions to maintain clear relationships between the message and its context.

### Hierarchy Principle
**Alert importance should be visually apparent.** Use appropriate types (error, warning, success, info) and styling to indicate the relative importance and urgency of different messages.

### Action Principle
**Alerts should guide users toward appropriate next steps.** When possible, include clear actions or links that help users address the situation or continue their workflow.

## Implementation

### Getting Started

```bash
npm install @inform-elevate/elevate-core-ui
```

### Basic Usage

```html
<!-- Basic alert -->
<elvt-alert type="info">
  This is an informational alert message.
</elvt-alert>

<!-- Alert with icon -->
<elvt-alert type="success" show-icon>
  Your changes have been saved successfully.
</elvt-alert>

<!-- Dismissible alert -->
<elvt-alert type="warning" closable>
  Your session will expire soon. Please save your work.
</elvt-alert>

<!-- Alert with custom icon -->
<elvt-alert type="error">
  <elvt-icon slot="icon" icon="mdi:alert-circle"></elvt-icon>
  Unable to connect to server. Please try again.
</elvt-alert>
```

### Key Properties

| Property | Type | Description |
|----------|------|-------------|
| `type` | `info` (default), `success`, `warning`, `error` | Alert type affecting styling and semantics |
| `variant` | `filled` (default), `outlined` | Visual style variant |
| `show-icon` | Boolean | Whether to display type-appropriate icon |
| `closable` | Boolean | Whether alert can be dismissed |
| `open` | Boolean | Controls alert visibility |

### Slots

| Slot | Description |
|------|-------------|
| Default | Alert content and message text |
| `icon` | Custom icon (overrides show-icon behavior) |
| `actions` | Action buttons or interactive elements |

### Events

| Event | Description |
|-------|-------------|
| `elvt-close` | Fired when alert is dismissed |
| `elvt-show` | Fired when alert becomes visible |
| `elvt-hide` | Fired when alert becomes hidden |

*For complete API reference including all properties, events, and methods, see the [Storybook documentation](https://elevate-core-ui.inform-cloud.io/?path=/docs/components-alert--docs).*

## Accessibility

### Essential Accessibility Practices

**ARIA support:**
- Alerts automatically include appropriate `role="alert"` or `role="status"` attributes
- Content changes are announced to screen readers
- Focus management for dismissible alerts
- Semantic markup for alert structure

**Visual accessibility:**
- Sufficient color contrast for all alert types (4.5:1 minimum)
- Clear visual indicators beyond color alone
- Consistent spacing and typography
- Support for high contrast mode

**Keyboard interaction:**
- Dismissible alerts can be closed with Escape key
- Action buttons are keyboard accessible
- Focus moves appropriately when alerts are dismissed
- Tab navigation follows logical order

**Screen reader support:**
- Alert content is announced when shown
- Type information is conveyed semantically
- Action instructions are clear and descriptive
- Status changes are communicated appropriately
