# Radio Group

Radio groups organize multiple radio buttons into a logical group, ensuring only one option can be selected at a time while providing consistent validation and accessibility features.

## Usage Guidelines

### When to Use
- **Mutually exclusive choices** - When users need to select exactly one option from a list
- **Form organization** - To group related radio buttons with shared validation
- **Accessibility** - When you need proper keyboard navigation and screen reader support
- **Validation** - When the group requires collective validation or error messaging

### When Not to Use
- **Multiple selections** - Use checkbox groups instead
- **Single options** - Use individual checkboxes for standalone choices
- **Large option lists** - Consider select dropdowns for 7+ options

## Component API

### Properties

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `label` | `string` | - | Accessible label for the radio group |
| `name` | `string` | - | Name attribute shared by all radio buttons |
| `value` | `string` | - | Currently selected value |
| `required` | `boolean` | `false` | Whether a selection is required |
| `disabled` | `boolean` | `false` | Disables the entire group |
| `invalid` | `boolean` | `false` | Marks the group as invalid |
| `help-text` | `string` | - | Helper text displayed below the group |

### Events

| Event | Description |
|-------|-------------|
| `elvt-change` | Fired when the selected value changes |
| `elvt-invalid` | Fired when validation fails |

### CSS Custom Properties

| Property | Description |
|----------|-------------|
| `--radio-group-gap` | Space between radio buttons |
| `--radio-group-label-color` | Color of the group label |

## Accessibility

### Keyboard Navigation
- **Tab** - Move focus between radio groups
- **Arrow Keys** - Navigate within a radio group
- **Space** - Select focused radio button

### Screen Reader Support
- Group label is announced when entering the group
- Individual radio labels and states are announced
- Required status and validation errors are communicated

### Best Practices
- Always provide a descriptive group label
- Use logical tab order in forms
- Include helper text for complex choices
- Ensure sufficient color contrast for all states

## Design Guidelines

### Layout
- Stack radio buttons vertically for better readability
- Use consistent spacing between options
- Align radio buttons and labels consistently

### Content
- Keep radio labels concise and descriptive
- Use parallel phrasing for all options
- Order options logically (alphabetical, frequency, etc.)
