# Mutation Observer

The Mutation Observer component provides a declarative way to observe DOM changes and react to modifications in the document structure, attributes, or content.

## Usage Guidelines

### When to Use
- **Dynamic content monitoring** - Watching for content changes in dynamic applications
- **Attribute tracking** - Observing attribute changes on elements
- **DOM structure monitoring** - Detecting when elements are added or removed
- **Reactive components** - Building components that respond to external changes
- **Accessibility updates** - Tracking changes that affect assistive technologies

### When Not to Use
- **Simple event handling** - Use standard event listeners for user interactions
- **Performance-critical operations** - Heavy DOM observation can impact performance
- **Static content** - Unnecessary for content that doesn't change after initial render

## Component API

### Properties

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `target` | `string \| Element` | - | Target element or CSS selector to observe |
| `child-list` | `boolean` | `false` | Observe additions and removals of child elements |
| `attributes` | `boolean` | `false` | Observe attribute changes |
| `character-data` | `boolean` | `false` | Observe text content changes |
| `subtree` | `boolean` | `false` | Observe all descendants, not just direct children |
| `attribute-old-value` | `boolean` | `false` | Record previous attribute values |
| `character-data-old-value` | `boolean` | `false` | Record previous text content |
| `attribute-filter` | `string[]` | - | Specific attributes to observe |
| `disabled` | `boolean` | `false` | Disable the observer |

### Events

| Event | Description |
|-------|-------------|
| `elvt-mutation` | Fired when observed changes occur |

### Event Details

The `elvt-mutation` event includes detailed information about the changes:

```typescript
interface MutationEventDetail {
  mutations: MutationRecord[];
  target: Element;
  observer: MutationObserver;
}
```

## Event Handling

### JavaScript Event Listener

```javascript
// Listen for mutations
document.addEventListener('elvt-mutation', (event) => {
  const { mutations, target } = event.detail;
  
  mutations.forEach(mutation => {
    switch (mutation.type) {
      case 'childList':
        console.log('Child nodes changed:', mutation);
        break;
      case 'attributes':
        console.log('Attributes changed:', mutation);
        break;
      case 'characterData':
        console.log('Text content changed:', mutation);
        break;
    }
  });
});
```

### Mutation Record Properties

Each mutation record includes:
- `type`: Type of mutation ('childList', 'attributes', 'characterData')
- `target`: The element that was modified
- `addedNodes`: Nodes that were added
- `removedNodes`: Nodes that were removed
- `attributeName`: Name of changed attribute
- `oldValue`: Previous value (if tracking enabled)

## Performance Considerations

### Optimization Tips
- **Specific targeting**: Use specific selectors rather than observing large trees
- **Minimal observations**: Only observe the changes you need
- **Throttling**: Consider throttling rapid changes in your event handlers
- **Cleanup**: Disable observers when no longer needed

### Memory Management
- Observers maintain references to observed elements
- Disable observers when components are destroyed
- Use weak references in long-lived applications

### Content Management

- Build reactive components that respond to external changes

Mutation observers can impact performance if overused. Only observe the specific changes you need and consider debouncing rapid changes in your event handlers.
